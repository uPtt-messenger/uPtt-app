01 運作方式

uPtt 如何把站內信變成對話

1995

站內信，一封一封都長得一樣

在 PTT 的信箱裡，每則來自 uPtt 的訊息都只是一行標題。要讀，得一封一封點開；要回，得重新寫一封信。

uPtt 在背景，替你讀懂每一封

每 5 秒輪詢一次信箱，辨識 uPtt 格式、還原內嵌的 [uPtt-ts] 時間戳，再從 PTT 刪除已收下的訊息，信箱永遠乾淨。

然後，它們變成一段真正的對話

依發送者歸入各自的對話、依時間排序，未讀數字亮在聯絡人旁。一般站內信不會被刪，原封不動留在 PTT。

04 架構

兩條連線，
互不等待

同一個 PTT 帳號，uPtt 同時開兩條連線：一條專心收發訊息，一條專門查詢線上狀態。查詢再慢，也拖不住你的訊息。

  • 主連線　登入、每 5 秒輪詢站內信與水球、送出訊息。
  • 查詢連線　主連線登入 10 秒後啟動，負責可能卡住數秒的使用者查詢；重連時絕不踢掉主連線。
  • 共用重連節流　兩條同時斷線時，以至少 5 秒的間隔排隊重連，避開 PTT 的「登入太頻繁」。
05 安全與隱私

你的對話，只存在你的電腦裡。沒有中繼伺服器，沒有帳號系統，沒有追蹤。

  • 01

    本地 SQLite

    對話紀錄與設定只存在本機的資料庫，多帳號以 account_id 完全隔離。

  • 02

    只連兩個地方

    直連 PTT 官方伺服器 ptt.cc；另外只向 GitHub API 查詢有沒有新版本。

  • 03

    程式碼簽章

    發行版由 SignPath.io 簽署、SignPath Foundation 驗證，確保下載的檔案沒被竄改。

  • 04

    CI 防洩漏

    TruffleHog 秘密掃描、Bandit 靜態分析、pip-audit，以及攔截密碼外洩的金絲雀測試。

使用 uPtt 時，請勿在其他 PTT 終端手動刪除信箱內容。

uPtt 依信件順序同步，手動刪信可能造成同步錯誤或誤刪。uPtt 只會刪除自己格式的訊息；若仍有疑慮，可在 PTT 設定中開啟「外部信箱備份」。
